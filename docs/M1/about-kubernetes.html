Module 1: About Kubernetes

Kubernetes (K8s) is an open-source system for automating the deployment, scaling, and management of containerized applications. It enables you to run containers reliably across a cluster of machines.

Key Terms

Cluster

A cluster is the complete Kubernetes environment: a set of machines and the software that runs on them to schedule, run, and manage containerized applications. A cluster typically consists of two logical parts:

  • Control Plane: The brain of the cluster. It exposes the Kubernetes API (allows you to run kubectl) and makes global decisions (scheduling, scaling, reconciliation). Key components include:
    • API Server — the front-end for the Kubernetes control plane. The Kubernetes API lets you query and manipulate the state of objects in Kubernetes. It is accessed via the API server and HTTP API.
    • etcd — the distributed key-value store that holds cluster state.
    • Controller Manager & Scheduler — controllers analyze desired vs. current state; the scheduler places Pods on nodes.
  • Worker Nodes: Machines that run application workloads (Pods) and node-level agents that maintain pod lifecycle and networking.

Node

A node is a single machine (virtual or physical) in the cluster that runs the services necessary to run Pods. Types of nodes:

  • Control Plane Node (sometimes called "master") — runs the control plane components listed above. In small clusters these may run on the same node as workloads.
  • Worker Node — runs Pods and node agents (kubelet, kube-proxy) plus a container runtime (containerd (RKE2), CRI-O, or Docker).

Nodes register with the control plane and report status/health so the cluster can schedule and reschedule workloads.

Pod

A pod is the smallest deployable unit in Kubernetes. It represents one or more tightly coupled containers that:

  • Share the same network namespace (IP address and ports) and can share storage volumes.
  • Are scheduled together onto the same node and have a shared lifecycle.

Common patterns and attributes:

  • Single-container pods for most apps; multi-container pods for sidecar or adapter containers.
  • Init containers run to completion before app containers start (used for setup tasks).
  • Restart policies and liveness/readiness probes control pod health and lifecycle behavior.
  • Labels and selectors let controllers and Services identify and group pods.

Kubelet

The kubelet is an agent that runs on each node. Its responsibilities include:

  • Registering the node with the control plane and reporting node and pod status.
  • Watching the API server for PodSpecs assigned to the node and ensuring the described containers are running via the container runtime.
  • Executing health checks and enforcing pod resource limits and lifecycle (start, stop, restart as needed).

Kube-proxy

kube-proxy runs on each node to implement Kubernetes networking rules for Services. It:

  • Maintains network rules that route traffic to the correct backend Pods for a Service.
  • Can operate in different modes (iptables or IPVS) to balance traffic and implement ClusterIP/NodePort behavior.
  • Ensures that Service endpoints are kept up-to-date as Pods scale or move.
